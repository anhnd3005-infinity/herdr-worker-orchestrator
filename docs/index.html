3-Layer Runtime

Why 3-Layer Orchestration Wins

Separate planning, process supervision, and code generation into distinct execution zones.

🧠

Layer 1

Claude Code

Plans milestones, decomposes tasks, writes briefings. Never writes unverified code directly.

✓ .agents/BRIEFING.md
✓ Task State Machine
✓ Crash recovery
⚙️

Layer 2

Herdr Multiplexer

Controls terminal panes, lifecycle polling, and injects automation APIs to manage real TTY sessions.

✓ Live Pane Split
✓ Plugin Actions
✓ Real TTY interaction
🤖

Layer 3

Isolated Workers

Executes with agy, codex, or any CLI. Worktrees isolate files; a Reviewer inspects diffs.

✓ Git Worktree isolation
✓ Skip permissions mode
✓ Diff-based verification

Core Capabilities

5 Superpowers

Engineered to solve real failure modes discovered during deep empirical testing.

#1 — Git Worktree Isolation Zero Pollution

Workers operate in isolated git worktrees on dedicated branches. No file conflicts. True parallel multi-agent development.

// Isolated tree architecture
Project/
├── main worktree ← Claude works here
├── .worktrees/TASK-001 ← Worker 1 (agy)
└── .worktrees/TASK-002 ← Worker 2 (codex)
#2 — Stateful Task Ledger

Every task lives in .agents/tasks/TASK-xxx.json with lifecycle state transitions. If Claude restarts, resume picks up with zero loss.

✓ Survives session compactions
#3 — Diff-Enforced Review

The reviewer subagent is forbidden from reading worker self-reports. It only inspects git diff, runs tests, and verifies assertions.

✓ Evidence before assertions
#4 & #5 — Smart Heuristics

stalled ≠ failed. Our script inspects terminal transcripts for delivery markers before deciding to wait vs retry. Auto-injection of --dangerously-skip-permissions prevents interactive hangs.

Old Way
stalled → abort → user frustrated
Our Way
stalled → read transcript → found marker → pass!
